libdcadec qualification vector provenance

The DTS elementary streams and mono PCM reference files come from
foo86/dcadec-samples commit 8665d5718888f2b9192516f86014cc3642ed653a.
Upstream explicitly releases these sample files into the public domain.

packets.json records FFmpeg DTS-demuxer packet byte ranges adjusted past the
DTS-HD file headers. It is validation metadata only. Production packets come
from Mediabunny's bounded container input.

core_51_24_48_768_0.mka is a deterministic, metadata-free Matroska remux of
the Core vector and verifies Mediabunny's A_DTS unknown-codec packet route.
The recorded remux command is:

  ffmpeg -fflags +bitexact -i core_51_24_48_768_0.dtshd -c:a copy -f matroska core_51_24_48_768_0.mka

Current FFmpeg builds write slightly different container bytes, so the
committed file is the reference.

dts-core-stereo.mka and dts-core-5.0.mka are FFmpeg's experimental DTS core
encoder's output (dca), one sine per source channel at amplitude 0.25 (FL 400,
FR 600, FC 800, SL 1000, SR 1200 Hz), in Matroska. They show which speaker mask
the dts package reports for a stereo and a 5.0(side) core and which plane
carries which channel. The recorded commands are:

  ffmpeg -fflags +bitexact -f lavfi -i "aevalsrc=0.25*sin(2*PI*400*t)|0.25*sin(2*PI*600*t):s=48000:c=stereo:d=0.16" -c:a dca -strict -2 -b:a 768k -flags +bitexact -f matroska dts-core-stereo.mka
  ffmpeg -fflags +bitexact -f lavfi -i "aevalsrc=0.25*sin(2*PI*400*t)|0.25*sin(2*PI*600*t)|0.25*sin(2*PI*800*t)|0.25*sin(2*PI*1000*t)|0.25*sin(2*PI*1200*t):s=48000:c=5.0(side):d=0.16" -c:a dca -strict -2 -b:a 768k -flags +bitexact -f matroska dts-core-5.0.mka

Other FFmpeg builds write slightly different bytes, so the committed files are
the references.
